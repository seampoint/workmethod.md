# Field report dispositions for package 1.0.1

These dispositions implement the publication-fix direction approved by Jeff Whatcott on October 26, 2026. The original reports are assistant self-assessments, not independently reproduced qualifications. Source issues: [1](https://github.com/seampoint/workmethod.md/issues/1) and [2](https://github.com/seampoint/workmethod.md/issues/2). Retain privacy-safe reproductions in public reports.

| Item | Disposition | Package 1.0.1 behavior or remaining limit |
|---|---|---|
| 1.1 Waiting dates | Clarified; new field deferred | Due applies to commitments and changes to them. Waiting dates remain Object prose. No Resurface field is added. |
| 1.2 Label identity | Clarified | One item through its history, not a topic. A separate new obligation gets its own Label. |
| 1.3 Outside findings and duplicates | Narrowed | Reconcile separately authorized outside findings with the applicable canonical record. No mandatory whole-tree scan on every write. Cross-tree discovery remains limited. |
| 1.4 Memory and correction destination | Clarified | Memory does not replace the work record. Disclose a host-policy conflict. Local methods name the destination for tree-wide corrections. |
| 1.5 Connector replacement | Clarified; general fallback deferred | Disclose inability to update in place. Use an explicitly approved method procedure or obtain fallback authorization. Never replace immutable entries. |
| 1.6 Coverage disclosures | Clarified | Briefs and factual work/status reports retain material Not checked limits, including when relayed. Empty conversational acknowledgments need no coverage report. |
| 1.7 Related trees | Deferred | Establish roots and canonical ownership in local methods. No implicit cross-tree access or writes. |
| 2.1 Connected-system activation | Deferred | Explicitly establish scope and methods; no promise of automatic activation for every CRM, mail or calendar action. |
| 2.2 Other canonical systems | Narrowed | Follow the applicable method's permitted destination and readback procedure; do not create a second file record. Disclose unavailable access. No claim of connected-system format conformance. |
| 2.3 Memory | Same clarification as 1.4 | Not a separate implemented feature. |
| 2.4 Coverage disclosures | Same clarification as 1.6 | Not a separate implemented feature. |
| 2.5 Missing practice | Clarified | Disclose missing maintenance and any stale derived file. A saved canonical event is not undone by a later maintenance failure. |

No deferred proposal is closed by this table. New fields, broader format boundaries and additional supported host routes require their own review and evidence.
